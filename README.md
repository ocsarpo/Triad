# Triad

Codex와 Claude를 한 채팅방에서 독립적으로 호출하는 macOS 앱입니다.

## 호출법

- `#codex 요청` — Codex만 메시지를 받습니다.
- `#claude 요청` — Claude만 메시지를 받습니다.
- `#all 요청` — 두 에이전트에게 동시에 직접 전달합니다.
- 입력창의 **둘 다 / Codex 고정 / Claude 고정**으로 태그 없는 요청의 기본 대상을 대화별로 정합니다. 새 대화는 **둘 다**가 기본입니다.
- `#codex`, `#claude`, `#all` 및 호환 `@codex`, `@claude`, `@all` 같은 명시 호출은 기본 고정보다 항상 우선합니다.
- `@"/프로젝트/문서.md"` — 프로젝트 문서를 해당 호출의 참조 파일로 지정합니다.
- 한글 별칭 `#코덱스`, `#클로드`, `#모두`도 지원합니다.
- 기존 `@codex`, `@claude`, `@all` 호출은 호환용으로 계속 지원합니다.
- 입력창에서 `#`을 치면 세 호출 대상을 표시하며, 방향키와 `Enter`로 자동완성할 수 있습니다.
- 입력창에서 `@`을 치면 Codex·Claude 작업 폴더의 파일을 검색합니다. Git 저장소에서는 `.gitignore`를 존중하고 변경 파일을 먼저 표시합니다.

한 메시지 안에서 AI별 지시를 나누면 각 구간은 해당 AI에게만 전달됩니다.

```text
공통 배경 설명
#codex:
API를 구현해줘

#claude:
보안 관점에서 설계를 검토해줘
```

위 예시에서 공통 배경은 양쪽이 받고, 구현 지시는 Codex만, 검토 지시는 Claude만 받습니다. `#all` 뒤의 구간은 두 AI가 함께 받습니다.

콜론이 붙은 `#codex:`, `#claude:`, `#all:`이 줄 맨 앞에 있으면 긴 명령을 위한 블록 모드가 됩니다. 다음 블록 헤더 전까지의 모든 줄이 해당 AI에게만 전달되며, 블록 안의 일반 `#codex` 문자열은 라우팅 태그로 해석되지 않습니다. 헤더 자체를 내용에 넣으려면 `\#codex:`처럼 이스케이프합니다. 입력창의 `블록 지시` 버튼으로 기본 템플릿을 삽입할 수 있고, 전달 미리보기에서 각 AI에게 실제 전송될 내용과 글자 수를 확인할 수 있습니다. 빈 블록은 전송 전에 차단됩니다.

메시지는 `Enter`로 전송하고 `Shift+Enter`로 줄바꿈합니다.

진행 방식은 네 가지입니다.

- **독립 실행** — 기존처럼 선택된 AI가 서로의 답을 보지 않고 독립적으로 작업합니다.
- **에이전트 협업** — 시작 AI가 필요한 단일 쟁점만 로컬 `ask_agent` MCP 도구로 상대 AI에게 질문하고, 도구 결과를 받아 같은 작업을 계속합니다.
- **상호 토론** — 시작 AI가 제안하고 상대 AI가 좁은 판정을 남깁니다. 이견이 있을 때만 한 번 해결한 뒤 시작 AI가 결론을 확정합니다.
- **교차 검토** — 위와 같은 제안 → 좁은 검토 → (필요 시 이견 해결) → 최종 결정 하네스를 사용합니다.

협업 모드에서 태그 없는 요청은 Codex·Claude 고정일 때만 그 AI를 **한 번의 실행**의 시작 AI로 사용합니다. **둘 다**는 협업 설정의 첫 발언 AI를 사용합니다. 명시한 단일 AI 태그는 고정보다 우선하며, `#all` 또는 두 AI를 함께 명시한 요청은 협업의 시작 AI를 하나로 정할 수 없어 전송 전에 안내합니다. 기본 대상 고정은 대화마다 저장되지만, 협업 설정 자체를 바꾸거나 이미 실행·대기 중인 작업에는 영향을 주지 않습니다.

에이전트 협업의 AI 간 호출 한도는 2·4·6·8·10회 중 선택할 수 있고 기본값은 2회입니다. 보조 AI 응답 제한은 1~120분(기본 5분)에서 설정할 수 있으며, 제한 도달 시 종료 사유를 채팅과 실행 과정에 표시합니다. 중첩 호출 깊이는 2단계로 제한됩니다. AI 호출이 시작되면 질문, 호출 횟수, 답변 또는 실제 오류가 채팅과 실행 과정에 표시됩니다. Codex와 Claude의 기존 MCP 설정은 유지되며 Triad 브로커는 해당 실행에만 임시로 추가됩니다.

협업 중에는 전체 대화나 이전 AI의 원문 답변을 다시 주입하지 않습니다. 대신 Triad가 프로젝트 밖 `~/Library/Application Support/Triad/Shared Context/`에 앱 전역 **공유 문서**를 관리합니다. 상단의 **공유 문서**에서 문서를 만들고, 이름을 바꾸고, 삭제하거나 현재 대화의 작업 문서로 선택할 수 있습니다. 선택한 문서는 앱·대화를 다시 열어도 유지되며, 새 협업은 같은 문서에 새 실행을 추가합니다. 화면에서는 현재 작업과 최신순 최대 20개의 접이식 실행 기록을 분리해 보여주며, 기록에는 의제·결론·담당 AI의 기여 요약이 남습니다. proposal/verdict/decision은 새 실행에서 초기화하므로 과거 결과를 현재 판정으로 재사용하지 않습니다.

상호 토론·교차 검토에서는 보드에 의제, 제약, 제안, 근거, 검토 판정, 이견, 최종 결정을 기록합니다. 시작 AI는 owner/proposer, 반대 AI는 reviewer가 되며 어느 쪽을 먼저 선택해도 같은 규칙이 적용됩니다. 독립 실행도 선택한 문서를 사용합니다. 한 번의 전송에서 Codex와 Claude는 같은 새 실행 문서에 각각 `submit_contribution`으로 요약·근거를 남기지만, 서로의 원문 답변이나 전체 기여를 강제로 주입받지는 않습니다. 협업 턴은 기존 대화 세션과 분리된 새 세션으로 실행되며, 필요한 파일·보드 섹션만 읽도록 안내됩니다. 작업 중 추가 전송한 메시지는 대기열에서만 보이다가 실제 실행을 시작할 때 채팅에 표시됩니다. 중지 버튼은 현재 실행만 중지하고, 협업의 남은 릴레이만 취소하며 이후 대기 작업은 유지해 이전 작업이 끝나는 즉시 이어서 실행합니다. macOS 표준 편집 단축키 `⌘X` 잘라내기, `⌘C` 복사, `⌘V` 붙여넣기, `⌘A` 전체 선택을 지원합니다.

AI 답변에 포함된 일반 `http`/`https` 주소와 마크다운 링크는 자동으로 클릭 가능한 링크가 되며, 기본 웹 브라우저에서 열립니다.

**변경 사항** 패널은 staged·unstaged 변경과 `.gitignore`를 존중한 신규 파일을 함께 파일별 unified diff로 표시합니다. 신규 바이너리는 Git의 바이너리 표시만 보여 주며, 512KB를 넘는 신규 파일 또는 전체 2MB를 넘는 diff는 일부만 표시합니다.

답변 스트리밍 중 사용자가 메시지 영역을 위로 스크롤하면 현재 위치를 유지합니다. 메시지 영역이 맨 아래가 아닐 때는 `↓ 맨 아래` 버튼이 표시됩니다. 사용자가 새 메시지를 보내면 즉시 맨 아래로 이동하고, 이후 다시 위로 스크롤하면 위치 고정이 재개됩니다.

상단 에이전트 상태에는 제공자가 전달한 5시간/주간(Claude는 7일) 한도의 남은 비율이 표시됩니다. Codex는 앱 실행 직후, 5분마다, 작업 종료 후, 수동 새로고침 시 계정 한도를 조회합니다. 조회 중과 실패 상태를 직접 표시하며 오류 원문은 실행 과정 패널에도 남깁니다. Claude는 각 작업 중 수신되는 최신 한도 이벤트를 즉시 반영하며 툴팁에서 초기화 예정 시각과 마지막 확인 시각을 볼 수 있습니다.

왼쪽 대화 목록에서 새 대화를 만들고, 이전 대화를 검색·이름 변경·삭제·재개할 수 있습니다. 대화마다 각 AI의 모델·추론 수준·속도, 작업 권한·폴더, 세션, 실행·대기 상태와 branch/files/diff 결과를 보존합니다. 실행 환경의 **공통 작업 폴더**가 기본이며, `에이전트별 작업 폴더 사용`을 켜면 Codex·Claude에 저장해둔 서로 다른 경로를 다시 사용합니다. 공통 모드로 바꿔도 각 AI의 기존 경로는 보존되므로 다시 켤 수 있습니다. 한 대화에서 AI가 실행 중이어도 다른 대화로 이동하거나 새 대화를 열어 메시지를 보낼 수 있으며, 서로 다른 대화에서는 같은 AI도 동시에 실행됩니다. 독립 실행에서는 Codex가 작업 중이어도 `#claude`처럼 비어 있는 한 AI만 지정한 요청은 즉시 시작하며, 반대도 같습니다. 독립 실행의 후속 요청에는 전체 대화 대신 호출 AI 자신의 최신 사용자 요청·답변 한 쌍만 최대 약 3,000자로 잘라 전달합니다. 이 작은 맥락은 “그것을 바꿔줘” 같은 수정 지시 해석용이며, 프로젝트의 현재 상태는 항상 직접 확인합니다. 세션이 재개되는 경우 직전 맥락은 이미 세션에 남아 있으므로 다시 주입하지 않고, 새 세션으로 회전할 때만 전달합니다. `ㅎㅇ?` 같은 짧은 인사·확인성 메시지는 프로젝트·git·공유 보드를 읽거나 기여를 남기지 않고 한두 문장으로 가볍게 답합니다. 같은 대화에서 동시에 시작한 단일 AI 요청은 하나의 독립 실행 공유 문서와 run ID를 재사용해 기여만 합칩니다. 다른 대화가 같은 공유 문서를 쓰는 중이면 문서 충돌을 피하기 위해 순차 대기하지만, 다른 문서라면 비어 있는 AI 슬롯을 바로 사용할 수 있습니다. `#all`처럼 여러 AI를 함께 호출한 요청은 대상 중 하나라도 바쁘면 묶음으로 대기합니다. 실행 스트림·오류·세션·대기 메시지는 시작한 대화에만 기록되고, 실행 중 또는 대기 중인 대화는 삭제할 수 없습니다. 메시지뿐 아니라 태그 없는 요청의 기본 대상, 각 AI의 설정, 세션 ID, 실행 로그도 대화별로 SQLite에 함께 저장됩니다.

오른쪽의 **실행 과정** 패널은 두 AI의 세션 시작, 모델 설정, 상태 변화, 도구 및 명령 실행, 재시도, 사용량, 종료 코드와 오류 원문을 실시간으로 보여줍니다. 모델의 비공개 내부 사고 원문은 표시하지 않습니다.

상단의 `실행 과정 숨기기/보기` 버튼으로 오른쪽 패널을 토글할 수 있습니다. 숨기면 채팅 영역이 확장되며 마지막 표시 상태는 앱을 다시 실행해도 유지됩니다.

호출되지 않은 에이전트의 세션에는 메시지가 들어가지 않습니다. 에이전트마다 모델, 추론 수준, Standard/Fast 속도, 작업 폴더, 권한 모드, 세션을 따로 관리합니다.

각 AI의 **세션** 설정에서 자동 회전(기본), 계속 유지, 항상 새 세션을 선택할 수 있습니다. 자동 회전은 일반 작업의 세션이 6턴 또는 **직전 요청에서 측정된 현재 문맥 48,000토큰**에 도달한 다음 작업부터 새 세션을 엽니다. 캐시를 포함한 논리 입력은 문맥 측정용이며 과금 추정이 아닙니다. 이전 답변 원문을 새 프롬프트로 복사하지 않고, 선택된 공유 문서의 이력·기여를 필요한 경우에만 읽어 연속성을 유지합니다. 전송 미리보기의 토큰 수는 UTF-8 문자 특성을 반영한 보수적 **추정치**입니다. 세션의 현재 문맥·누적 입력은 CLI 사용량 이벤트 기반 논리 토큰이며, 제공자의 실제 청구 토큰 또는 과금액과는 다를 수 있습니다.

인증은 기존 Codex/Claude CLI 로그인을 그대로 쓰거나 API 키 모드를 선택할 수 있습니다. API 키는 앱 설정이나 대화 기록에 평문으로 저장하지 않고 macOS 키체인에 보관합니다.

앱은 시작 시와 24시간마다 `ocsarpo/Triad`의 최신 공개 GitHub Release를 확인합니다. 현재 앱보다 높은 버전이 있으면 헤더에 릴리스 링크를 표시하며 자동 다운로드나 자동 설치는 수행하지 않습니다.

공유 문서 실행 기록에는 `TR-…` 고유 ID가 표시됩니다. **참고** 또는 AI 답변의 **답장**은 `@실행[ID]`를 입력하며, 요청당 최대 3개 기록의 목표·결론·최신 기여 요약만 압축 참고합니다.

대화 목록은 클릭·설정 저장 시각이 아니라 실제 사용자·AI 메시지 활동 시각 기준으로 최근순 정렬됩니다.

## 개발 환경 준비

`ocsarpo/Triad` 저장소를 클론하면 소스·빌드 스크립트·테스트가 모두 포함됩니다. 재생성되는 산출물(`.build/`·`.module-cache/`·`dist/`)만 제외되므로, 아래만 갖추면 이어서 빌드할 수 있습니다.

**빌드 도구 (macOS)**
- Xcode Command Line Tools — `clang`용. `xcode-select --install`
- Python3 + Pillow — 아이콘 생성(`scripts/build-icns.py`)에 필요. `pip3 install Pillow` (없으면 빌드가 아이콘 단계에서 실패)
- sqlite3·Cocoa·WebKit 등 프레임워크는 macOS 기본 제공

**코드 서명 (선택, 권장)**
- 재빌드·업데이트에도 macOS 폴더/“다른 앱 데이터” 접근 권한(TCC)이 초기화되지 않게 하려면 고정 서명 인증서를 한 번 만듭니다.

  ```bash
  zsh scripts/create-signing-cert.sh              # 로그인 키체인에 "Triad Self-Signed" 생성
  export TRIAD_SIGN_IDENTITY="Triad Self-Signed"  # ~/.zshrc 에 넣어두면 매번 자동 적용
  ```

  지정하지 않으면 ad-hoc 서명으로 빌드되어 빌드마다 권한이 초기화됩니다. 인증서는 머신마다 키가 다르므로 권한 승인은 다른 머신으로 이전되지 않습니다.

**실행 런타임 (빌드 외)**
- Node.js — 에이전트 협업 MCP 브로커 실행용(Homebrew·Volta·로컬 경로 자동 탐색)
- `codex` / `claude` CLI — 앱이 호출하는 에이전트. 설치 후 각 CLI 로그인 또는 API 키가 필요합니다.

**빌드·테스트**

```bash
node --test Tests/*.test.cjs   # 단위·정적 테스트
zsh scripts/package-app.sh     # dist/Triad.app 생성
```

## 앱 패키징

```bash

```

앱 본체는 AppKit과 WebKit 시스템 프레임워크를 사용합니다. 에이전트 협업의 로컬 MCP 브로커는 Node.js를 사용하며, 앱이 일반적인 Homebrew·Volta·로컬 설치 경로에서 실행 파일을 자동 탐색합니다.
